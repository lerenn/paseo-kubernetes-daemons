# Migrating to 0.5.0 (BREAKING: "workspaces" → "daemons" naming)

0.5.0 renames everything this project owns from *workspaces* to *daemons*. Paseo's own concept of a
"workspace" (workspace UIDs, `create_workspace`, the Overview "Workspaces" section) is unchanged, and so
are the `paseo` namespace, `paseo-providers.json` and the `kubernetes-gateway/...` host source key.

| Before | After |
| --- | --- |
| plugin id `kubernetes-workspaces` | `kubernetes-daemons` |
| `ghcr.io/lerenn/paseo-workspaces-operator` | `ghcr.io/lerenn/paseo-daemons-operator` |
| `ghcr.io/lerenn/paseo-workspace` | `ghcr.io/lerenn/paseo-daemon` (files in `/usr/local/lib/paseo-daemon/`) |
| chart `oci://ghcr.io/lerenn/charts/paseo-workspaces` | `oci://ghcr.io/lerenn/charts/paseo-daemons` |
| release / namespace default `paseo-workspaces` | `paseo-daemons` |
| `paseo-workspaces-gateway[-tls\|-auth]` | `paseo-daemons-gateway[-tls\|-auth]` |
| CRD `paseoworkspaces.workspaces.paseo.sh` (`PaseoWorkspace`) | `paseodaemons.daemons.paseo.sh` (`PaseoDaemon`) |
| labels/annotations `workspaces.paseo.sh/*` | `daemons.paseo.sh/*` |
| env `PASEO_WORKSPACE_*`, `PASEO_WORKSPACES_GATEWAY_*` | `PASEO_DAEMON_*`, `PASEO_DAEMONS_GATEWAY_*` |

The CRD group changes, so existing `PaseoWorkspace` objects are **not** converted: the new operator never
sees them. Run the two stacks side by side, then retire the old one.

## What the plugin migrates for you

Paseo scopes plugin settings by installation id (`<PASEO_HOME>/plugin-settings/<plugin id>/…`) and offers
no API to read another plugin's data. On first start under the new id, 0.5.0 copies the old
`kubernetes-workspaces/workspace-setup.json` into the new id's directory, **only if the new one does not
exist** (a best-effort file copy). It rewrites namespace `paseo-workspaces` → `paseo-daemons`, resets a
default old image to the new default, and clears the sync digest so the next sync re-uploads.
Context, cluster id, providers, projects and plugins carry over.

If the copy did not happen (different `PASEO_HOME`, new id already saved, daemon in a container with a
different data dir), copy it by hand on the main daemon host, then reload the plugin:

```sh
cd "$PASEO_HOME/plugin-settings"          # usually ~/.paseo/plugin-settings
mkdir -p kubernetes-daemons
cp -n kubernetes-workspaces/workspace-setup.json kubernetes-daemons/
```

Edit the copied file: set `namespace` to the new namespace and drop `image` and `synced` (or just re-enter
them in the screen). Host registrations belong to the plugin that created them; the new plugin registers
its own gateway host, and the old one disappears when the old plugin is removed.

## Cluster migration (homelab-anyshift, documentation only)

1. **Install the new chart next to the old one**, in its own namespace:
   `helm install paseo-daemons oci://ghcr.io/lerenn/charts/paseo-daemons --version 0.5.0 -n paseo-daemons --create-namespace <your values>`.
   Re-apply the plugin RBAC (`paseo-daemons-plugin` Role and `…-storageclasses` ClusterRole) and bind them to
   the main daemon's ServiceAccount (see `docs/setup.md`).
2. **Copy provider Secrets** (the ones referenced by your providers/projects, with their
   `daemons.paseo.sh/*` labels renamed from `workspaces.paseo.sh/*`) and the pull Secret:
   `kubectl -n paseo-workspaces get secret <name> -o yaml | sed 's/workspaces\.paseo\.sh/daemons.paseo.sh/g' | kubectl -n paseo-daemons apply -f -`
   (strip `namespace`, `uid`, `resourceVersion`, `ownerReferences` first). Do the same for the
   `projects.json` / providers ConfigMaps if you manage them by hand; the gateway ConfigMap and auth Secret
   are regenerated by the new plugin and operator.
3. **Install the new plugin id** `kubernetes-daemons` (0.5.0) on the main daemon; the settings are carried
   over as described above. Open **Kubernetes Daemons**, check the namespace, run the sync and confirm the
   new gateway host connects.
4. **Recreate environments** under the new operator (`PaseoDaemon` objects are new); verify them.
5. **Remove the old stack last**: uninstall the old plugin `kubernetes-workspaces`, delete old
   `PaseoWorkspace` objects, `helm uninstall paseo-workspaces -n paseo-workspaces`, delete the old CRD
   (`kubectl delete crd paseoworkspaces.workspaces.paseo.sh`) and namespace.
